import {Bin, BinX, Density, Dot, Replot, Rect, RectY, RuleY, TreeMark} from "@dave-hillier/replot/react";
import * as d3 from "d3";
import {useOlympians} from "./data/olympians.ts";
import {sidebar} from "./sidebar.ts";

export const docPaths = (() => {
  const base = import.meta.env.BASE_URL.replace(/\/$/, "");
  const paths = [];
  (function visit(node, path) {
    paths.push({path, href: node.link && (node.link.startsWith("http") ? node.link : base + node.link)});
    if (node.items) {
      for (const item of node.items) {
        visit(item, (path === "/" ? path : path + "/") + item.text);
      }
    }
  })({items: sidebar}, "/Replot");
  return paths;
})();

export function computeTreeWidth(paths) {
  const root = d3.tree().nodeSize([1, 1])(d3.stratify().path((d) => d.path)(paths));
  const [x1, x2] = d3.extent(root, (d) => d.x);
  return x2 - x1;
}

# What is Replot?

**Replot** is a free, open-source, JavaScript library for visualizing tabular data, focused on accelerating exploratory data analysis. It has a concise, memorable, yet expressive interface, featuring [scales](./features/scales.md) and [layered marks](./features/marks.md) in the *grammar of graphics* style popularized by [Leland Wilkinson](https://en.wikipedia.org/wiki/Leland_Wilkinson) and [Hadley Wickham](https://en.wikipedia.org/wiki/Hadley_Wickham) and inspired by the earlier ideas of [Jacques Bertin](https://en.wikipedia.org/wiki/Jacques_Bertin). And there are [plenty of examples](https://observablehq.com/@observablehq/plot-gallery) to learn from and copy-paste.

Replot is a **declarative React component API** for building charts with JSX, on top of a powerful shared core — D3 scales, transforms, projections, and mark types. See the [getting started guide](./getting-started.md) to begin.

In the spirit of *show don’t tell*, here’s a scatterplot of body measurements of athletes from the [2016 Summer Olympics](https://flother.is/2017/olympic-games-data/).

<Replot color={{legend: true}}>
  <Dot data={useOlympians()} x="weight" y="height" stroke="sex" />
</Replot>

A plot specification assigns columns of data (*weight*, *height*, and *sex*) to visual properties of marks (**x**, **y**, and **stroke**). Replot does the rest! You can configure much more, if needed, but Replot’s goal is to help you get a meaningful visualization quickly to accelerate analysis.

This scatterplot suffers from overplotting: many dots are drawn in the same spot, so it’s hard to perceive density. We can fix this by applying a [bin transform](./transforms/bin.md) to group athletes of similar height and weight (and sex), and then use opacity to encode the number of athletes in the bin.

<Replot>
  <Bin fillOpacity="count">
    <Rect data={useOlympians()} x="weight" y="height" fill="sex" inset={0} />
  </Bin>
</Replot>

Or we could try the [density mark](./marks/density.md).

<Replot>
  <Density data={useOlympians()} x="weight" y="height" stroke="sex" />
</Replot>

A simpler take on this data is to focus on one dimension: weight. We can use the bin transform again to make a histogram with weight on the *x*-axis and frequency on the *y*-axis. This plot uses a [rect mark](./marks/rect.md) and an implicit [stack transform](./transforms/stack.md).

<Replot>
  <BinX y="count">
    <RectY data={useOlympians()} x="weight" fill="sex" />
  </BinX>
</Replot>

Or if we’d prefer to show the two distributions separately as small multiples, we can [facet](./features/facets.md) the data along *y* (keeping the *fill* encoding for consistency, and adding grid lines and a rule at *y* = 0 to improve readability).

<Replot grid>
  <BinX y="count">
    <RectY data={useOlympians()} x="weight" fill="sex" fy="sex" />
  </BinX>
  <RuleY data={[0]} />
</Replot>

## How Replot differs from Observable Plot

Replot is a fork of [Observable Plot](https://observablehq.com/plot/) that keeps its grammar — marks, scales, transforms, projections — but restructures how plots are expressed and rendered for React. The differences run deeper than a wrapper:

**The renderer is React itself.** Observable Plot builds SVG imperatively with D3 selections and returns a detached element you insert into the page. In Replot, every mark renders to JSX, and the `<Replot>` component renders a plot as an ordinary React subtree. There is no manual DOM insertion, and plots participate in reconciliation and Suspense like any other component. On the server, `renderToString` returns the whole plot; a hydrating client redraws it, because marks register with the plot from an effect.

**Marks are components; a plot is composition.** Where Plot takes a `marks: [...]` array of mark objects, Replot layers sibling components inside `<Replot>`. Under the hood this uses a two-phase render: mark components register their configuration with the enclosing `<Replot>` through context, the plot computes scales and layout from everything registered — the same whole-plot inference Plot performs — and then each mark renders its SVG. Adding, removing, or reconfiguring a mark through React state recomputes the plot automatically.

**Transforms nest instead of wrapping options.** Plot's transforms compose functionally — `Plot.binX(outputs, Plot.stackY(options))` — with one mark's options split across nested calls. Replot expresses the same composition as component nesting, so the JSX structure mirrors the grammar:

```jsx
<Replot>
  <BinX y="count">
    <StackY>
      <RectY data={athletes} x="weight" fill="sex" />
    </StackY>
  </BinX>
</Replot>
```

Input channels stay on the mark; outputs and transform configuration go on the wrapper. The functional form remains supported — both run the identical transform functions.

**Everything else follows the same principle.** Scales can be declared as components (`<ScaleY grid type="log" />`) as well as props; legends are components that register with the plot rather than DOM appended after the fact; marks accept per-datum event handlers (`onClick`, `onPointerEnter`) that receive the underlying datum; and pointer interactions like [tips](./marks/tip.md) and [crosshairs](./interactions/crosshair.md) are driven by React state rather than D3 event listeners.

**What is deliberately unchanged.** The computational core is shared with Observable Plot: D3 scales and shape generators, channel and scale inference, the data transforms, geo projections, and the default styles. A chart specified in Replot renders the same pixels as its Observable Plot equivalent — the difference is how you express it, not what you get.
